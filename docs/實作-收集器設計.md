# 實作-收集器設計（collector 效能 / 常駐 / 聚合）

> 點樣高效、唔打擾 vLLM 咁收集。來源：研究 R3 + sparktop/sparkscope/spark-mon/spark-smi。

---

## 各指令真實成本（GB10, 20-core ARM big.LITTLE）

| 指令 | 延遲 | 註 |
|---|---|---|
| sysfs/proc（thermal/meminfo/stat/loadavg） | 0.1–1ms | 近乎免費（X725 eff core 行） |
| **resident NVML**（`nvidia-ml-py`，唔開子程序） | **50–300µs** | 最快正路，唔好 spawn |
| `nvidia-smi --query-gpu` | 10–50ms | 成本係 **subprocess spawn**（fork+NVML init），2–5s 做一次 OK；**唔好 per-tick exec** |
| `watch nvidia-smi`（每 1s re-spawn） | — | 論壇實測令 tight inference loop **慢 ~20%** → 唔好咁做 |
| `ethtool -S` 喺 ConnectX-7 hw counters | 1–50ms | 每 group **trap 入 NIC firmware**，好貴；只慢 tier + cache |
| NVMe `smart-log` | 5–100ms（可 block） | **最貴**，admin queue；只慢 tier 60–120s，skip-on-timeout |
| `iostat` | 5–15ms | 直接讀 `/proc/diskstats` 自己計 delta 更平 |

> 底線：唯一唔可忽略嘅係 **subprocess spawn**（nvidia-smi/ethtool/NVMe）＋ **ethtool firmware trap**＋ **NVMe SMART**。sysfs/proc 全部 sub-ms 近乎免費。

## 三層 polling（確認）

- **fast 2–5s**：GPU（resident NVML + sysfs）util/temp/power/clocks、CPU/RAM、thermal、netdev。**唔含** NVMe/ethtool-firmware。
- **slow 30–60s**：`docker ps`、df/partition、fabric counters（單次 cached `ethtool -S`）、systemctl inventory。
- **very slow 60–120s**：NVMe SMART、hardware inventory。SMART 要 skip-on-timeout。

## 常駐模式（✅ 推薦）

- **long-lived resident daemon**：background loop 更新 shared **in-memory snapshot**；HTTP handler **淨係 O(1) 讀 snapshot** → request rate 影響唔到 GPU/host（唔好 per-request collect）。
- **remote node（Node-B）**：**單一 batched SSH script** 一次過 return 晒 fast-tier fields（SSH round-trip 150–890ms，batching amortize；**唔好每 metric 開新 ssh**）。
  - 技巧（sparktop/sparkscope）：一個 script 用 `---SECTION---`/ASCII-RS separator ＋ 每 section 一行 command；`check=False`/不逐 section 失敗。
  - 一次 exec 攞：`nvidia-smi --query-gpu`、hwmon temp scan、`free`、`/proc/stat`、`/proc/meminfo`、netdev、RDMA counters。
- **resource budget**：<2–5% 一個核心（band 到 X725 eff core，nice 19 / cgroup `cpu.max`/`cpu.weight`）＋ <50MB RAM；**零 GPU work**。
- **concurrency**：asyncio（`asyncssh` 或 `asyncio.create_subprocess_exec("ssh",...)`）。N=2 時 thread vs async 分別不大，但 asyncio 乾淨。agentless SSH batch 推薦；只有要 sub-2s remote freshness 先要 resident agent。

## 唔好打擾 vLLM / LLM serving（關鍵）

1. **永遠唔 spawn GPU work**：零 CUDA context、零 torch、零 clock-locking。NVML query 唔會搞亂 GPU clock（慢係 subprocess re-spawn，唔係讀 clock）。
2. **resident NVML reader**，唔 per-tick `exec` nvidia-smi。
3. **Budget host CPU**：nice 19 + cgroup 限、pin eff core、jitter polling phase。
4. **唔好喺 inference write-heavy 時讀 NVMe SMART**（admin queue 會 block）→ 60s skip-on-timeout guard。
5. **ethtool firmware trap**：只 slow tier + cache（vLLM distributed 可能靠 fabric）。
6. **Memory-pressure awareness**：collector keep heap <50MB；讀 `/proc/pressure/memory`(PSI) gate anomaly logging（唔好狂打 NVMe）。

## Snapshot / API 層（借 sparktop 模式）

- **in-memory `ClusterSnapshot`**：`{ts, nodes[], fabric.summary, warnings[], totals}`，coalesced 更新（~90% fast interval）。
- `/metrics`、`/api/snapshot`、WS 全部係**同一個 snapshot 嘅 cached projection** → scrape ~0.4ms、node 慢唔會拖死收集。
- `warnings[]`：node unreachable/offline、sensor hot、disk≥90%、GPU-clock fault、VRAM≥95%、fabric link fault。
- **rate 用 measured dt**（唔好 nominal interval——SSH exec latency 唔均勻）。
- **dedupe/counter**：counter reset（數字跌返）→ rate=0 + re-baseline；latency 用 rolling window（`_sum/_count`）。

## N 節點聚合（確認——支援 2..N 部 DGX）

- **一部 aggregator**（`aggregation.pull: all-except-self`）拉晒 `nodes[]` 唔係自身嗰啲，經 **10GbE mgmt IP** 合併出 `/health`+`/cluster.json`。
- 每部都**各自 run exporter**（一等公民）；加/減一部唔影響其他。
- **關節點 graceful**：node down → `status:"offline"` + `error_message`，request 唔 5xx；`asyncio.gather` 並行拉，一部 hang 唔 block 其他。
- **N 大時**：Prometheus federation / 多級 aggregator / agent+pull-from-daemon（全部 cached snapshot）。
- ⚠️ vLLM 端口：跨節點 Ray 得一部 :8000；每節點獨立就 `nodes[].vllm_port` 記。
- 全詳見 **[實作-多節點擴展.md](實作-多節點擴展.md)**。

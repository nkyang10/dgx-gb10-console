# 狀態-04 · 儲存 / 磁碟（每節點）

> collector：`collectors/system.py` ｜ 優先級：⭐必備（空間 + NVMe health）
> ⚠️ **此平台有已知 "No NVMe Device Found" 故障**（NVIDIA 論壇有記錄）→ NVMe SMART 值得監。

---

## Filesystem 用量

| 資料 | 點攞 | 單位 |
|---|---|---|
| 空間 | `df -PB1 /`（或 `os.statvfs`，唔 spawn） | bytes（size/used/avail/use%） |
| I/O 吞吐 + iops | `/proc/diskstats` delta ×512 bytes/sector | ops + sectors/Δt |

- ⚠️ 過濾：skip `squashfs/tmpfs/devtmpfs/overlay`、`/snap/`、`/dev/loop`（spark-mon 做法）

---

## NVMe SMART / 健康（⚠️ 慢，60–120s slow tier）

| 資料 | 點攞 | 關鍵字段 |
|---|---|---|
| 身份 | `sudo nvme list` / `nvme id-ctrl /dev/nvme0` | model、size、firmware |
| SMART/健康 | `sudo nvme smart-log /dev/nvme0n1`（nvme-cli v3 改 `sudo nvme log smart`）│ `smartctl -j -a` | `critical_warning`、`temperature`、`available_spare`、`percentage_used`(wear)、`data_units_written/read`、`unsafe_shutdowns`、`media_errors`、`power_on_hours` |
| 自測/溫度 | `sudo smartctl -H` `/dev/nvme0n1` | health、temperature |

- ⚠️ smartot stow 需要 `nvme-cli` / `smartmontools`（`apt install`），可能有需要 passwordless sudo。
- ⚠️ SMART 係**最貴**嘅讀（admin queue，5–100ms，可 block）→ 只喺 slow tier 60–120s、每 drive 一個、skip-on-timeout。

---

## ✅ 建議收（每節點）

- `disk.<mount>.total_bytes/used_bytes/used_pct`（⭐ 空間）
- `disk.read_iops/read_mbps/write_iops/write_mbps`（🟡 從 diskstats delta）
- `nvme.temp_c`、`nvme.spare_pct`（available_spare）、`nvme.used_pct`（wear）、`nvme.media_errors`、`nvme.critical_warning`（⭐ 健康，slow tier）

## 🚨 相關警報

- **DiskSpaceHigh/Critical**：`/`、`/var` >85%（10m/warn）/>95%（5m/crit）
- **NvmeCriticalWarning**：`critical_warning > 0`，`for:0m` — crit
- **NvmeMediaErrors**：`media_errors > 0`，`for:0m`
- **NvmeAvailableSpareLow**：`available_spare < threshold + 10`，`for:0m`
- NVMe wear（percentage_used）>85 warn / >95 crit（可選）

> Prometheus 替代：node_exporter `node_filesystem_*`/`node_nvme_*`；SMART 用 **textfile collector** parse `nvme log smart`（observability 做法）。

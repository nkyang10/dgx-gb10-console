## 1. 部署方案（DGX OS, Ubuntu 24.04 ARM64）

**結論：每節點 bare Python venv + systemd；Node-A 做 aggregator 經 10GbE mgmt IP 拉 Node-B。Docker 係 opt-in 後備。**

| | venv + systemd（✅） | Go binary | Docker |
|---|---|---|---|
| 讀 host telemetry | 直接 /proc、/sys、nvidia-smi | 要重寫 collectors | 要 `network_mode: host` + bind-mount host /proc//sys//usr/bin |
| 依賴 | pip venv，arm64 wheels 齊 | cross-compile | multi-arch build + NVIDIA toolkit caveat |
| GPU data | `nvidia-ml-py` 或 nvidia-smi（host service） | 重寫 pynvml | **唔好加 `--gpus`**（host-level collect） |
| Footprint | ~150MB | ~10MB | ~200MB + daemon |

**DGX OS 內建可用**：`python3`(3.12)、curl、ip、lspci、gcc、nvidia-smi、**Docker CE + nvidia-ctk**。**可選 apt 裝**：`nvme-cli`、`lm-sensors`、`ethtool`（install.sh best-effort；缺咗 collectors graceful handle）。

**systemd unit**（`deploy/dgx-status-exporter.service`，已備）：
- `User=status` / `Group=status` unprivileged
- `ExecStart=.../uvicorn app.main:app --host 0.0.0.0 --port ${DGX_STATUS_PORT:-9101}`
- `EnvironmentFile=/etc/dgx-status/status.env`（root 0600）
- `Restart=always`、hardening（`NoNewPrivileges`/`ProtectSystem=strict`/`PrivateTmp`/`ProtectKernelTunables`/`CapabilityBoundingSet=` 全清）

**2 節點 config**（`config/config.yaml`，已備）：Node-A `role:aggregator`（拉 peer `node-b:10.0.20.11:9101`）；Node-B `role:exporter`；static 列表 default、`auto_discover`(mDNS) off、`remote_collect`(SSH 無 agent) fallback。**recommendation：每節點 exporter + HTTP pull**。

**install flow**（`scripts/install.sh`，冪等）：
```bash
git clone <repo> ~/dgx-status && cd ~/dgx-status
sudo ./scripts/install.sh --mode=host                 # Node-A
openssl rand -hex 32 | sudo tee /etc/dgx-status/status.env >/dev/null
sudo ./scripts/install.sh --mode=host --role=exporter  # Node-B
sudo ./scripts/install.sh --update                     # 升級；--uninstall 回滾
```
**依賴**（`requirements.txt`）：`fastapi` `uvicorn[standard]` `pydantic` `pydantic-settings` `psutil` `nvidia-ml-py` `prometheus-client`（optional `python-socketio`）。ARM64 wheels 全部齊。

## 2. 安全（含站與站 Communication）

- **Bind 去 mgmt-LAN IP**（`--host 192.168.50.11`）唔好 `0.0.0.0`；firewall default-deny inbound。
- **API-key/Bearer**：token 由 **env `DGX_STATUS_TOKEN`**（唔好 argv）＋ `HTTPBearer(auto_error=False)` ＋ 常數時間 `secrets.compare_digest`；**API read-only（default-deny）**，冇 POST/reboot。Optional `X-API-Key`。
- **TLS**：出外（consumer）用 **Caddy reverse proxy**（uvicorn 綁 loopback）；跨節點可 mTLS。
- **Inter-node hop（aggregator→exporter）** —— ⚠️ 唔好淨係 plaintext + shared token：
  - **Default**：隔離嘅 mgmt VLAN（自 switch、唔出 internet）＋ **每 node 各自 token**（唔好全 cluster 同一個）。
  - **要離信任邊界／LAN 唔可信** → 用**加密 tunnel（WireGuard/Tailscale mesh）**（aggregator 經 `127.0.0.1` tun 拉 exporter）或 **mTLS**（每 node cert，兩邊互相認證）。
  - `/logs`、`/control` proxy 行同一 internal hop，同一標準；**control 另加 authorization**（邊個 node 開咗 control）+ 冪等 + dry-run。
- **vLLM `:8000`** 預設 `0.0.0.0` 係 expose 咗 → **firewall 收返做 inside**（淨 loopback/mgmt）。
- **hardening**：rotate 預設 DGX Dashboard/OpenBMC creds、prod 關 `/docs`、token `chmod 600`、**永遠唔好 log token**、proxy 度 rate-limit、SQLite `.backup`。

## 3. 歷史儲存

- **SQLite WAL**：tall `samples(node,ts,metric,value,meta)` + `idx(node,ts)`+`idx(metric,ts)`；30d ≈ 1.7M rows fine；`DELETE ts < now-30d`，可 >7d 降採樣 1/10-min。sparkscope 用 `metrics(host,category,metric,value)` wide-to-long。
- live 用 in-memory ring buffer（`deque(maxlen)`）畀 `/history?last=5m`；真正 30d+ 用 **Prometheus TSDB**（避免 double 存）。TimescaleDB rejected（2 nodes overkill）。

## 5. ✅ 警報閾值（PromQL，DGX 特定 failure modes）

| 警報 | 邏輯 | 嚴重度 |
|---|---|---|
| NVMeCriticalWarning | `critical_warning` >0，`for:2m` | crit |
| NVMeWearHigh/Critical | `percentage_used` >85 /95 | warn/crit |
| DiskSpaceHigh/Critical | `/`、`/var` >85%/95% | warn/crit |
| GPUHot / GPUThrottle | temp >92 / **>96**（GB10 throttle line） | warn/crit |
| SMClockCollapse（USB-C PD 故障） | `SM_CLOCK/SM_CLOCK_MAX<0.45` AND util>80，`for:2m` | crit |
| ConnectXLinkDown | `phys_state!=1`；RDMADead `port_state!=4` | crit |
| VllmEngineDead | `probe_success==0`；FailedSystemdUnit；exporter `up==0` | crit |
| HostMemoryHigh/Critical | RAM>85%/95%（+swap） | warn/crit |
| NodeExporterDown → inhibit | `up==0` 抑制同 host 其他 | crit |

> 完整 rule 內容 + schema + code 喺 `references/安全-監控-alert.md`。

## 6. Log 睇/拎（read-only，ASM-20）

兩層：
1. **輕量 markers**（已設計，D3）：每來源 `{count, last_ts}` 入 snapshot → 警報。
   ```
   kernel_oom_24h, kernel_nvme_error_24h, kernel_thermal_24h, vllm_requests_logged
   ```
2. **on-demand tail**（read-only endpoint，aggregator 經 mgmt IP 去節點）：
   ```
   GET /api/nodes/{node}/logs/{source}?lines=200&since=&filter=
     source = vllm | kernel | services | <container-name>
   # backend: journalctl -u/-k / docker logs --tail N
   ```
   - 限行數（≤500）、`since` 限時窗、`filter` 用 grep（要 timeout，唔好 hold 太耐）
   - 每個 tail 請求要 timeout（~3–5s），防 journalctl 卡死
   - **要 auth**（vLLM request log 可含 prompts/tokens；token 存 env，**唔好 log token**）
   - Loki 全文搜尋 = 可選（OD-5），2 節點用 `journalctl`/`docker logs` 已夠。

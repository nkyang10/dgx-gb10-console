# 實作 · 多節點擴展（支援 2..N 部 DGX）

> 將設計由「寫死 2 節點」擴大到 **N 部 DGX cluster**。2 部係最基本部署；架構支援一路加到 N。
> config 已改通用（`config/config.yaml` 有 `nodes[]` 註冊表）；install.sh 已參數化（`--node-id`/`--role`/`--mgmt-ip`）。

---

## 1. 架構 —— 單 gateway + N leaf（星型）

```
                 +------------------+    (mgmt 10GbE switch)
                 |   GATEWAY        |   = dgx-01, role=gateway
                 |   dgx-status API  |   (FastAPI :9101)  ← 你呢部機 call
                 +--------+---------+
                          | 拉晒 nodes[] 其他部（HTTP :9101 Bearer token）
              +-----------+-----------+-----------+
              |           |           |           |
        +-----+---+   +---+-----+   +---+-----+
        | dgx-02 |   | dgx-03 |   | dgx-0N |
        | exporter|  | exporter|  | exporter|   (leaf, 只暴露本地 :9101 /metrics)
        +---------+   +---------+   +---------+
              └────── ConnectX-7 200G fabric（全網/NCCL，唔用嚟 mgmt）──────┘
```

- **一部 gateway**（Node-A）：跑自己嘅 exporter＋拉晒 `nodes[]` 唔係自身嗰啲（`gateway.pull: all-except-self`）→ 合併成 **ClusterSnapshot** 出 `/health` + `/cluster.json` + `/metrics`。
- **其餘每一部 leaf**：`role=exporter`，淨係喺自機 `:9101` 暴露本地 /metrics（+ 自己嘅 vLLM）。
- 想再擴：加多部 → 一係加做 leaf，一係（節點太多時）**多級 gateway / federation**（見 §5）。

### 角色對稱性
- 兩部機都**各自 run exporter**（唔係「一部淨問另一部」）→ 每部都係一等公民，加/減一部唔影響其他。
- gateway 拉 leaf 用 **10GbE mgmt IP**（唔用 ConnectX fabric）—— fabric 全畀 NCCL/compute。

## 2. N 節點 config（`config/config.yaml`）

```yaml
cluster:
  name: "dgx-cluster"
  role: "gateway"        # 本機角色（install.sh/status.env 覆寫）
  node_id: "dgx-01"          # 本機 id（必須喺 nodes[] 出現）
  mgmt_cidr: "10.0.20.0/24" # mgmt 網段

nodes:                       # 全 cluster 註冊表 —— 加機就加一行
  - { id: dgx-01, mgmt_ip: 10.0.20.10, role: gateway, port: 9101, vllm_port: 8000 }
  - { id: dgx-02, mgmt_ip: 10.0.20.11, role: exporter,    port: 9101, vllm_port: 8001 }
  # - { id: dgx-03, mgmt_ip: 10.0.20.12, role: exporter,    port: 9101, vllm_port: 8002 }

gateway:
  pull: "all-except-self"   # 或明確 pull: [dgx-02, dgx-03]
  auto_discover: false       # mDNS (224.0.0.251:5353) 可選
  connect_timeout_s: 5
```

**現有 2 部 DGX**：`nodes[]` 放 dgx-01（gateway）+ dgx-02（exporter）——即係你原本嗰個部署，唔使改架構。

## 3. vLLM 端口分配（N 節點最易撞嘅位）

vLLM 部署形態決定點分配端口：

| 形態 | 有幾多個 vLLM API | 端口 | 狀態 API 點撈 |
|---|---|---|---|
| **跨 N 節點單 server**（Ray，`--tensor-parallel-size N`） | 1 個（喺 Node-A） | `:8000` | 只撈 Node-A 嘅 :8000（Ray 只係 shard compute） |
| **每節點獨立 single-TP** | N 個 | 每節點 `:8000`（要 IP 分） | 每節點 `node.mgmt_ip:8000` 分開撈 |

⚠️ 每節點獨立 server 時：`network_mode: host`/`--host 0.0.0.0` → 節點之間用 IP 分，port 唔使改；但**同一部機**如果行多個 server 就要唔同 port（`nodes[].vllm_port` 記錄）。
→ 即係 config `nodes[].vllm_port` 預設 `8000 + index` 都 OK，但跨節點 Ray 個 case 就全部係 8000（得 Node-A 有）。**collector 照 `nodes[].vllm_port` 讀即可，唔使估。**

## 4. Fabric 全網配對（N 節點）

- 2 節點：單條 ConnectX-7 link 直接對連（`bond0` / 單條 DAC）。
- N 節點：fabric 通常**全網 mesh**（每 pair 一條連結）或經一個 ConnectX/ROCE switch。
- 狀態 API 嘅 `fabric.summary` 要做**所有 pair 數**嘅 link 配對（A-tx≈B-rx 交叉確認，`CONFIRM_RATIO`）；link count = C(N,2) 或 switch port count。
- RDMA per-link 讀法同 2 節點一樣（`ethtool vport_rdma` + IB counters ×4）——只係 iterate 多啲 iface/pair。
- ⚠️ ConnectX-7 packetstr Multi-Host → 每 physical port 出 2 個 OS iface → N 節點 = 每節點 4 個 iface，fabricmap 要正確 map ibdev↔netdev。

## 5. 擴展極限 + 多級聚合

- **單 gateway 拉 N leaf**：okay 到一個數量級（幾十部內）。每部慢 150–890ms SSH / HTTP round-trip 都係 async `asyncio.gather` 並行，唔累增；但 gateway 本身係單點。
- **N 好大時**：
  - **Prometheus federation**：每部（或每 rack）一個 Prometheus 收自已 exporter，中央 Prometheus federate —— 狀態 API 只撈中央。
  - **多級 gateway**：一部 master gateway 淨係拉幾部 mid-level gateway。
  - 或 **agent + pull-from-daemon**（部部機自己 resident poller 持有 snapshot，master 淨係 HTTP pull cached snapshot —— 唔使 per-tick SSH）。
- **單點風險**：gateway down → 照樣每部 leaf :9101 獨立可 call（唔係單一失敗）。

## 6. 加一部節點（流程）

```bash
# 1) 喺 config.yaml nodes[] 加一行（全部機同步 config）
nodes: ... - { id: dgx-03, mgmt_ip: 10.0.20.12, role: exporter, port: 9101, vllm_port: 8002 }

# 2) 喺新機（同一 repo）：
sudo ./scripts/install.sh --role=exporter --node-id=dgx-03 --mgmt-ip=10.0.20.12
openssl rand -hex 32 | sudo tee /etc/dgx-status/status.env >/dev/null   # 同 cluster 同一 token

# 3) gateway 自動出現 dgx-03 喺 snapshot（pull: all-except-self 會拉埋）
```

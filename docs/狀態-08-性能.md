# 狀態-08 · 性能（Performance）—— 吞吐 / 延遲 / 系統效能

> collector：`collectors/vllm.py`（推理性能）＋ `collectors/system.py`/`network.py`（系統性能）
> 優先級：⭐必備（推理性能係呢個 status API 最想知嘅嘢）
> 概念：**狀態** = 健康/用量快照；**性能** = 做緊嘢嘅**率（throughput）＋ 延遲（latency）**，要用 counter/histogram over 時間窗度。

---

## 0. 點解要「度率」唔係「抄數」

vLLM `/metrics` 俾嘅係**累計 counter**（`prompt_tokens`、`generation_tokens`、`request_success`）同 **histogram**（latency）。要變「性能」必須：
- **counter → rate**：記 prev value+ts，`rate=(cur−prev)/(t−t_prev)`；**counter reset（cur<prev，e.g. engine restart）→ rate=0 + re-baseline**。
- **histogram → latency**：avg = `_sum/_count`（rolling 窗）；**P95 = `histogram_quantile(0.95, sum by(le)(rate(_bucket[5m])))`**。
- **窗**：throughput 用 ~10s（speculative 要平均）；latency 用 ~60s；唔好1s即時（好嘈）。

## 1. vLLM 推理性能（來源：`/metrics`，10–15s scrape）

| 性能指標 | 計算 | 來源 metric |
|---|---|---|
| **decode tok/s** | `rate(generation_tokens_delta)` | `vllm:generation_tokens` |
| **prefill tok/s** | `rate(prompt_tokens_delta)`；**computed** = `prompt − cached`（減 prefix hit） | `vllm:prompt_tokens`、`vllm:prompt_tokens_cached` |
| **總吞吐** | `decode + prefill`（鍛造） | 上兩項 |
| **RPS**（完成 req/s） | `rate(request_success)` | `vllm:request_success{finished_reason}` |
| **TTFT** | avg `_sum/_count`；P95 用 `_bucket` | `vllm:time_to_first_token_seconds` |
| **ITL/TPOT**（inter-token latency） | avg＋P95 | `vllm:inter_token_latency_seconds`（另一名 `request_time_per_output_token_seconds`） |
| **e2e latency** | avg＋P95 | `vllm:e2e_request_latency_seconds` |
| **queue time** | avg（排隊排幾耐） | `vllm:request_queue_time_seconds` |
| **preemption rate** | `rate(num_preemptions)` | `vllm:num_preemptions` |
| **prefix-cache hit rate** | `rate(prefix_cache_hits) / rate(prefix_cache_queries)` | `vllm:prefix_cache_hits/queries` |
| **KV cache 用率** | 直接 gauge | `vllm:kv_cache_usage_perc` |
| **具體測decode 速度** | `1000 / ITL_ms` = per-request tok/s | derived |
| **SLO goodput**（可選） | 喺 latency budget 內完成嘅 request 比例 | `request_success` + latency histogram |
| **spec-decode（可選）** | acceptance rate / mean accepted length | `vllm:spec_decode_*`（如用） |

⚠️ 版本敏感：legacy 名 `_total` 尾 / `time_per_output_token_seconds` ↔ 現代名對照見 [狀態-07-vLLM.md](狀態-07-vLLM.md) §版本 pin。所有 metric 有 `model_name` label → 可以 per-engine 出 performance。

## 2. 系統性能（來源：proc/sys，平）

| 性能指標 | 計算 | 來源 |
|---|---|---|
| **網絡吞吐** | `/proc/net/dev` `rx/tx bytes` delta → B/s；**fabric RDMA** 用 HB counters ×4 → percept | `狀態-05` |
| **磁碟 IOPS + MB/s** | `/proc/diskstats` sectors delta ×512 → ops/s + sectors/Δt | `狀態-04` |
| **CPU util** | `/proc/stat` busy jiffy delta | `狀態-02` |
| **GPU util** | `nvidia-smi utilization.gpu` | `狀態-01` |
| **GPU SM/時脈健康** | clocks + throttle（性能 drop 偵測） | `狀態-01` |
| **memory pressure (PSI)** | `/proc/pressure/memory`（memory only） | `狀態-02` |

## 3. Performance 輸出形态（呈現場，同 API 未定方案掛鉤）

- **JSON**：每 node `{ vllm: {tokens_per_s, ttft_avg/p95, itl_avg/p95, rps, kv_cache, prefix_hit}, system: {net_rx/tx_bps, disk_iops, net_fabric_gbps, cpu_pct} }`
- **Prometheus**（如揀 exporter 路）：`_ratio`/SI units、`tokens_per_second` gauge、`latency_seconds` summary→rate。
- 快照 snapshot 已 cache → `/metrics`/JSON/WS 全部同一個 performance projection（sparktop 模式）。

---

## 4. 相關警報

- **Hightoken throughput** 唔係警報（係指標）；警報係**退化**：
  - `tokens_per_s` 突然跌 + GPU util 高 → 可能 throttle／KV 樽頸
  - `queue/latency` 急升（`request_queue_time` p95↑、`num_requests_waiting`↑）→ 積壓／慢
  - preemption rate 高 → KV 唔夠，建議 shrink model／加 node／調 KV
  - TTFT/ITL p95 超 SLO → latency 唔合格

---

## 5. 一句總結

**性能 = 率＋延遲**：vLLM 出 `tokens/s`、`RPS`、`TTFT/ITL/e2e/queue`（avg＋P95）、`KV-cache`、`prefix hit`；系統出 `network B/s`（＋fabric RDMA）、`disk IOPS/MB/s`、`CPU/GPU util`。全部由 counter/histogram 喺時間窗度出，唔好抄即時數。

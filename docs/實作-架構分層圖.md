# 實作 · 架構分層 Review（dependency / parallel / exposure）

> 目的：釐清成個設計嘅**分層** —— 邊啲 top-down 依賴、邊啲 parallel、邊啲 open to outside vs inside。
> 出處：SPEC §4 架構 + 各 `狀態-*`/`實作-*`。

---

## 0. 一睇過：分層（L4 頂 → L0 底，依賴向下）

```
 L4   CONSUMER（outside）     你部機 · Prometheus · Grafana · alertmanager
      ════════════▲══ OUTSIDE ◀──▶ INSIDE 邊界（HTTP, auth 區別）══
 L3   API / SERVICE 層          aggregator (Node-A)：FastAPI :9101
      │                          /health(OPEN) /cluster.json /metrics
      │                          /logs(AUTH)   /control(AUTH, opt-in)
      │                          ↑ 內部 cache 咗嘅 ClusterSnapshot
      └──────────┬───────────┬───────────┬───────────   (pull, mgmt IP, token)
 L2   EXPORTER 層（per-node）   dgx-01 exporter ｜ dgx-02 exporter ｜ dgx-0N exporter
      │           每部獨立 :9101，serve 自 node 嘅 snapshot
      ├───── 每 node 內部 ─────
 L1   COLLECTOR 層（parallel）  hardware · system · network · services · vllm（+perf）
      │           彼此獨立，asyncio/threads 並行
 L0   DATA SOURCE 層（inside）  nvidia-smi/NVML · /proc · /sys(hwmon) · journalctl ·
      │           docker · vLLM :8000 · ConnectX-7 RoCE/RDMA · NVMe SMART
```

---

## 1. Top-down 依賴（邊個 call 邊個，一層一層落）

| 方向 | 由 | 去 | 靠咩 |
|---|---|---|---|
| L3→L2 | **aggregator**（Node-A） | 每一部 exporter（含自己） | HTTP pull（`:9101`，Bearer token），`aggregation.pull: all-except-self` |
| L2→L1 | exporter | 自家 5 個 collector | 共享 in-memory `ClusterSnapshot`（background loop 填） |
| L1→L0 | collector | 數據源 | `nvidia-smi`/NVML、read `/proc`/`/sys`、`docker ps`/`journalctl`、HTTP 撈 **vLLM `/metrics`/`/health`/`/v1/models`/`/is_sleeping`**、RDMA counters |
| L4→L3 | 你部機/Prometheus | api | HTTP（見 §3 exposure） |

**單向**：collector 唔會 call 返 exporter；exporter 唔會直接 call aggregator（只被 pull）；consumer 唔會掂 L0–L2。→ **依賴係 strict top-down，冇環**。

---

## 2. Parallel（邊啲同時跑）

| 平行度 | 邊啲 | 機制 |
|---|---|---|
| **N 節點平行** | dgx-01..0N 嘅 exporter 同時各自收集 | 彼此獨立（一等公民）；aggregator 用 `asyncio.gather` 並行拉晒 |
| **每 node 內 collector 平行** | hardware / system / network / services / vllm | 一個 event loop 派 N 條 task；三層 tier（fast 2–5s / slow 30–60s / NVMe 60–120s）各自 timer |
| **3 層 polling parallel** | fast/slow/slowest 各自 tick | 唔互相 block（各自 background loop） |
| **rate-fig 平行** | /metrics 現行版"器 + 其他 | — |

> 冇共享狀態衝突（snapshot 係 append/updated dict，讀嘅係 cached 版本）→ 唔使 lock 都好穩。

---

## 3. Exposure 邊界（邊啲 OPEN to outside、邊啲純 INSIDE）

**🟢 OPEN 出外（consumer 摸得到，經 10GbE mgmt / network，要 auth 分級）：**
| Endpoint | 位置 | 認證 |
|---|---|---|
| `GET /health` | aggregator L3 | **OPEN（liveness，唔 auth）** |
| `GET /cluster.json` / `GET /metrics` | aggregator L3 | **AUTH**（`X-API-Key`/Bearer `DGX_STATUS_TOKEN`；read-only） |
| `GET /api/nodes/{n}/logs/*` | aggregator L3（proxy 去 leaf） | **AUTH**（⚠️ vLLM log 有 prompts/tokens） |
| `POST /control/*`（若 OD-4 開） | aggregator L3（proxy 去 leaf） | **AUTH + opt-in guarded**（abort-by-id/pause/resume；dry-run） |

**🔵 INSIDE 純內部（只喺節點之間，唔出外）：**
| 組件 | 位置 | 註 |
|---|---|---|
| exporter `:9101`（每 leaf） | L2 | 只俾 aggregator pull；bind mgmt 網/勿 0.0.0.0 出 internet |
| collector→數據源 | L1→L0 | 全 node-local |
| vLLM `:8000` | L0 | ⚠️ **vLLM 預設 `0.0.0.0:8000` 係 expose 咗**（10GbE + ConnectX 都摸到）→ 要 firewall 限定先唔當"出外" |
| DGX Dashboard `127.0.0.1:11000` | L0 | 純 loopback（內部） |
| RDMA/fabric（ConnectX-7） | L0 | NCCL/compute，唔入 status API |

**邊界規則：**
- **一切出去嘅嘢（L3 API）預設 read-only + auth**；`/health` 例外（淨 liveness，唔洩漏 fleet size）。
- **控制（control）**：opt-in，且係 aggregator 自己做 proxy（唔 raw pass-through），每個 action 先 dry-run「影響 N running/M waiting」。
- **其他嘗試出外嘅 port**（vLLM :8000）要靠 firewall 收返做 inside；DGX Dashboard loopback 已 safe。

---

## 4. 一句總結

- **Layer**（top→down 依賴）：**L4 Consumer → L3 API/aggregator → L2 exporter → L1 collectors → L0 data sources**，strict、單向、冇環。
- **Parallel**：N 節點平行（一等公民）＋ 每節點內 5 個 collector 平行 ＋ 三層 polling 各自 tick。
- **Exposure**：**出外淨係 aggregator 嘅 API**（`/health` open；其餘 auth + read-only；control opt-in）；**exporter/vLLM/fabric 都係 inside**（vLLM :8000 要 firewall 封實）。

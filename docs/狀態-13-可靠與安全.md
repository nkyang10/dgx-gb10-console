> **D** 健康/可靠（🟡）＋ **E** 網絡深（🟡）+ **F** 安全（🟢）｜ 來源：R5(R2-retry)+R6 research

## D — 健康 / 可靠性

### D1 · NVMe 壽命預測（🟡）
```bash
sudo nvme smart-log /dev/nvme0n1     # v3: sudo nvme log smart
```
- **⚠️ 單位更正**：`data_units_written` 係 **1000-byte units**（×1000 = bytes），**唔係 512KB**！公式：`bytes_written = data_units_written × 1000`。
- **GB10 最佳估計 = 用 vendor `percentage_used`**（4TB drive 真實 TBW 未必 expose）：
  `days_remaining = (100 − pct_used) × power_on_hours / pct_used / 24`
- 警報：`pct_used >85 warn / >95 crit`；`days_remaining <180d warn / <60d crit`；`critical_warning>0` crit（已知 GB10 "No NVMe Device" path）；`available_spare<10%` warn；`temp>70` warn。⚠️ SMART slow tier 60–120s 先讀。

### D2 · Container OOM/restart（🟢）
```bash
docker inspect --format '{{.Name}} | State.Running={{.State.Running}} | Health={{.State.Health.Status}} | Restarts={{.RestartCount}} | OOMKilled={{.State.OOMKilled}} | ExitCode={{.State.ExitCode}}' $(docker ps -aq)
docker events --filter event=oom --filter event=die --since 24h
```
- **排冧偵測**：keep baseline per ctr `{restart_count, ts}` → `restart_rate > 3/hour` = crash-loop（crit）；OOMKilled true → warn；**ExitCode=137（OOM SIGKILL）vs 143（SIGTERM）**。
- ⚠️ GB10：UMA → container mem 同 system 共用 128GB，OOM 常係 **CPU-side system OOM**（要 cross-ref `/proc/meminfo`+D3 log 歸因）；`gpu_memory_utilization=0.8` 有近-OOM 凍結 box 風險。slow tier 30–60s。

### D3 · Kernel/OOM log forensics（🟡，markers over Loki）
```bash
journalctl -k --since "24 hours ago" | grep -cE 'Out of memory|oom-kill|Killed process'
journalctl -k --since 24h | grep -iE 'nvidia.*(error|fail|warning)|NVRM|Xid'
journalctl -k --since 24h | grep -iE 'thermal|throttl|tj_max'
journalctl -k --since 24h | grep -iE 'nvme.*(error|fail)|No NVMe Device|I/O error'
```
- surface `{kind→count, last_ts}` 喺 SQLite，唔使 Loki（2 nodes 用 markers 夠）。可選 `journalctl --cursor` 增量。
- ⚠️ **優先用 `journalctl`（rsyslog/kern.log 可能冇 active）**；`task ... blocked/hung_task` = 凍結前兆（GB10 hard-power-off failure mode）；OOM 可以係 CPU memory（UMA）唔淨 GPU。

### D4 · 風扇 / EC / 節流史
- **D4a 風扇 RPM：❌ 唔 expose**（`fan.speed` N/A、hwmon 冇 fan node）→ 用**溫度 profile proxy**（持續高溫+高負載+功率）＋ **EC/firmware version change**（`fwupdmgr get-devices`，`0x0300` EC 有 fans-silent bug→rollback 0x02）做 monitor 觸發。
- **D4b 節流 timeline：✅ 可行（NVML）**：
```python
import pynvml; pynvml.nvmlInit(); h=pynvml.nvmlDeviceGetHandleByIndex(0)
r = pynvml.nvmlDeviceGetCurrentClocksThrottleReasons(h)   # bitmask
# flags: HW_SLOWDOWN(1<<5) THERMAL(1<<10) HW_THERMAL_SLOWDOWN(1<<13) HW_POWER_BRAKE(1<<14) SW_THERMAL(1<<15) SW_POWER_CAP(1<<17) ...
```
- **state machine（~2s tick）**：入 throttled → 紀錄 start/peak_temp/mask；出 → append `{start, duration, peak_temp, reason}`；rolling `throttled_minutes_per_hour`。
- 警報：單次 `>120s warn, >5min crit`；`throttled_min/hr >15 warn / >30 crit`；`temp>95°C sustained>1min crit`；**HW_SLOWDOWN 優先於 SW cap（hardware-level）**。
- ⚠️ ignore `GPU_Idle` reason（正常）；`clocks.sm <0.45×max + util高 + 非 idle` = USB-C PD fault（見 狀態-09）。

## E — 網絡深

### E1 · RDMA 擁塞（🟡）
RoCE bypass kernel → 讀 **HCA hardware counters**（`/sys/class/infiniband/mlx5_*/ports/*/`）：
```bash
grep . $HCA/ports/$PORT/hw_counters/{cnp_sent,cnp_handled,ecn_marked_roce_traffic,port_xmit_wait,out_of_seq} 2>/dev/null
grep . $HCA/ports/$PORT/counters/{out_of_sequence,rnr_nak_retry_err,req_transport_retries_exceeded,port_rcv_errors} 2>/dev/null
```
- **語義**：`cnp_sent`=我哋係擁塞源、`cnp_handled`=上游擁塞、`ecn_marked`=fabric congested、**`port_xmit_wait`=最決定性 RoCE 擁塞 tell**、`rnr_nak_retry`=peer backlog、`req_transport_retries_exceeded`=**硬失敗 QP error**。
- ⚠️ `hw_counters/*` = **4-byte words ×4**；`counters/*` = event counts，**唔好混**。
- **score = rate deltas（re-baseline on reset）**；alert 用「**rising vs rolling baseline ×3** + sustained 2min」，**唔好絕對閾值**。⚠️ single-node（一台 DGX）RoCE 多數 loopback → `xmit_wait≈0`，唔好 false-alarm。effort：低–中（`cnp_*`+`xmit_wait` 可以 5–10s poll）。

### E2 · NVLink/PCIe util + 拓撲 —— **厘清**（❌ 唔好 build NVLink monitor）
- **GB10 = 單一 SoC**，NVLink 係 **chip-internal**（Grace↔Blackwell on-die coherence = UMA）→ **冇 inter-chip NVLink link counter 可攞**。`nvidia-smi nvlink.*` = N/A/unsupported。
- 跨 Spark fabric 係 **ConnectX-7 RoCE**（唔係 NVLink）→ 真係要「NVLink util」其實係度 **RDMA/fabric（E1）**。
- **真正要睇嘅互連 = PCIe**（ConnectX-7 NIC 同 NVMe 都係 PCIe-attached）：
  - 拓撲：`lspci -tv`；link gen/width：`lspci -s <bdf> -vvv | grep LnkCap|LnkSta`
  - bandwidth counters：`/sys/bus/pci/devices/*/counters/{PCIE_TRANSACTION_TX, PCIE_DATA_TX/RX}`（有先 read）
  - `util% = (PCIE_DATA_TX+RX rate) / (link gen×width)`；`nvidia-smi pcie.*` = N/A
- ⚠️ GB10 inference 嘅 GPU↔memory path 係**內部 SoC fabric，唔經 PCIe** → 過份睇 ConnectX/NVMe PCIe util 意義唔大。effort：低（per-tick 兩個 counter ≈ 免費）。

## F — 安全

### F1 · Security posture snapshot（🟢 低）
```bash
ss -H -tlnp 2>/dev/null | awk '{print $4,$6,$7}'        # listening ports + owner
systemctl --no-legend --type=service --state=running list-units | awk '{print $1,$4}'
journalctl _COMM=sshd --since -1h | grep -ci 'Failed password'    # brute-force
last -i -F -n 15; who -a
find /root -type f -perm -4000 2>/dev/null               # SUID changes = red flag
```
- 每小時 snapshot（JSON）→ **diff vs 前一個** → alert：新 listener/service/SUID、`failed_ssh_1h>N`、authorized_keys 增加。
- ⚠️ GB10：**DGX Dashboard（127.0.0.1:11000 loopback）= 合法 listener 唔好 flag**；**vLLM 預設 0.0.0.0:8000 係 expose 咗**（10GbE + ConnectX 都有人摸到）——除非 firewall；有 NVIDIA default account 要 enumerate 對 baseline，唔好 hardcode allowlist。

### F2 · Service-anomaly vs baseline（🟢）
- Baseline = **vllm-serve + docker(nvidia-toolkit) + sshd**（+ systemd + loopback dashboard）。
```bash
ps -eo comm --no-headers | sort -u > /tmp/procs_now.txt
comm -23 /tmp/procs_now.txt /etc/dgx-spark/allowed_procs.txt   # NEW unknown procs
docker ps --format '{{.Names}}' | sort -u > /tmp/cont_now.txt
comm -23 /tmp/cont_now.txt /etc/dgx-spark/allowed_containers.txt
```
- Alert：新 process/container（未知 binary，high）、vLLM 消失（crit）、新 running systemd unit、SUID change。
- ⚠️ **vLLM 嘅 ps comm 會係 `python`/`uvicorn`** → 用 **systemd unit / listening :8000 / `pgrep -f vllm`** match，唔好用 `comm`；`dockerd`/`containerd`/`containerd-shim`/`nvidia-container-runtime` 係**正常**要 allowlist；**FW/driver update 後要 re-baseline**；vLLM sleep（weights_offloaded）**processes 仲喺度**，唔好當 fewer-procs 係健康信號。

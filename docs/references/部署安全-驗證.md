### 1b. Auth dependency — `src/api/security.py` (FastAPI API-key/Bearer, token-in-env)

```python
# src/api/security.py
import logging, os, secrets
from fastapi import Depends, HTTPException
from fastapi.security import HTTPAuthorizationCredentials, HTTPBearer

log = logging.getLogger("dgx_status.security")

# Load ONLY from env (never argv -> /proc/<pid>/cmdline / ps / shell history).
_token = os.environ.get("DGX_STATUS_TOKEN")
if not _token:
    _token = secrets.token_urlsafe(32)
    log.warning("DGX_STATUS_TOKEN unset; generated ephemeral token (callers locked out on restart)")

_bearer = HTTPBearer(auto_error=False)

async def require_token(
    credentials: HTTPAuthorizationCredentials | None = Depends(_bearer),
) -> None:
    """Dependency for every authenticated endpoint. API is read-only by design."""
    if credentials is None or not secrets.compare_digest(credentials.credentials, _token):
        raise HTTPException(status_code=401, detail="invalid token",
                            headers={"WWW-Authenticate": "Bearer"})
```

Wire-up in `src/api/main.py`:
```python
from fastapi import FastAPI, Depends
from .security import require_token

app = FastAPI(docs_url=None, redoc_url=None, openapi_url=None)   # disable /docs on prod

@app.get("/health")                     # public, no auth (probe)
async def health(): return {"status": "ok"}

@app.get("/api/v1/status", dependencies=[Depends(require_token)])
async def status(): ...                 # read-only snapshot

@app.get("/api/v1/log", dependencies=[Depends(require_token)])
async def log(service: str = "vllm"): ...  # AUTHED — see 1c. DO NOT expose open.

# No POST/PUT/DELETE anywhere. Mutations are default-deny (absent).
```

### 1c. Log-endpoint spec (vLLM request logs are SENSITIVE — must be authed + redacted)

vLLM `--log-requests` lines carry full proms/payload snippets (model, prompt prefix, request
metadata) — treating them as low-sensitivity is an information-disclosure bug. Spec:

```markdown
## GET /api/v1/log
- Auth:  REQUIRED  -> Dependency(require_token) (Bearer, constant-time compare)
- Params: service = vllm | systemd | nvidia | storage
          tail    = int, 1..2000 (default 500)
          grep    = optional substring filter (applied post-fetch, server-side)
- Source: systemd journal (journalctl -u <unit> -n N --no-pager)
          + vLLM stdout (json-file/k8s logs via docker logs for container path)
- Response: {"service": "vllm", "node": "a", "lines": ["...", ...], "total": N}
- CRITICAL:
  1. REDACT in-app before returning: strip Authorization headers and regex out
     bearer tokens + api keys (`sk-[A-Za-z0-9]{16,}` and `Bearer \S+` -> `***`).
  2. vLLM --log-requests is ON by default; prompt payloads leak into journalf/
     logs. Consider `--disable-log-requests` in prod unless debugging, OR keep
     the log endpoint authed AND LAN-only (never public NIC).
  3. Do NOT log the Authorization header at the app layer (access-log redaction).
  4. Bind this endpoint's listener to mgmt LAN only (see 1d).
- Access: also written to audit: every /api/v1/log call -> JSON to errlog (who/what/ts),
  so token usage is reviewable (small volume server-level access log is fine).
```

## (2) CORRECTIONS to the current repo (`/root/dgx-status/deploy`)

1. **`--host 0.0.0.0`** (unit + compose) contradicts the round-5 defense-in-depth binding
   guidance. Bind to the **mgmt-LAN address** (`--host 10.0.20.10` / `10.0.20.11`), or 127.0.0.1
   behind a Caddy/nginx reverse proxy. 0.0.0.0 on both 10GbE (OOB) and QSFP upstream exposes
   the token-bearing API beyond the trusted LAN. → Fix: bind mgmt-LAN or loopback+proxy.
2. **`DevicePolicy=closed` + `CapabilityBoundingSet=` (empty) is good**, but the unit comment
   claims host tools (nvidia-smi/dcgmi/nvme-cli subprocess) reach /proc,/sys from the unit's
   mount namespace. With `ProtectSystem=strict` + `PrivateMounts` (implied by ProtectSystem),
   systemd-built binaries/`/usr` in a strict ro namespace **may fail if they exec binaries with
   interpreter paths not visible**. For a pure-python `/proc`+`/sys` collector this is fine, but
   the nvme-cli/`smartctl`/`lspci` subprocess claim is fragile under `ProtectSystem=strict`.
   → Add `SystemCallFilter=@system-service` and, if executing host `nvme`/`smartctl`, bind-mount
   those binaries read-only (as the compose file already does via `/usr/bin`→`/host/usr/bin`)
   and call `/host/usr/bin/…` or drop `ProtectHome` on /home/status for ssh-less path. Simpler:
   keep collection pure-Python (nvidia-smi via NVML bindings, meminfo via /proc) and keep the
   strict namespace.
3. **vLLM request-log sensitivity is NOT addressed** in the README/compose. Add the log-endpoint
   auth + redaction spec (1c). Also decide `--disable-log-requests` on the vLLM command in prod.
4. **`RestartCount`/`State.OOMKilled` introspection for both systemd and Docker** not in repo —
   see (3) for the journal/docker-inspect markers to bake into `scripts/install.sh` health checks.
5. **README token line is wrong**: `openssl rand -hex 32 | sudo tee /etc/dgx-status/status.env`
   overwrites the whole env file (killing DGX_STATUS_PORT/ROLE/MGMT_IP). Use
   `echo "DGX_STATUS_TOKEN=$(openssl rand -hex 32)" | sudo tee -a` or edit in place; chmod 600.
6. **`--workers 1`** is correct for a cheap read-only telemetry API (no shared-state perf gain,
   keeps in-memory snapshot simple). Keep. `--access-log` should be on the proxy, not the app
   (avoid recording Authorization header); if kept, ensure redaction.
7. **SystemCallFilter/`AmbientCapabilities`** not set in the unit → add `SystemCallErrorNumber=EPERM`
   + `SystemCallFilter=@system-service` and explicit empty AmbientCapabilities. `CapabilityBoundingSet=`
   is set, but AmbientCapabilities reverts to bounding set only when empty + NoNewPrivileges.
8. **`LimitNPROC`/`LimitCORE`** not set → add modest values (a scrape, not a reverse proxy).

## (3) 2026 CHANGES (systemd / Docker API) — what to watch

**systemd (verified in latest man, v256+ current in 2026):**
- `ProtectProc=` (invisible|ptraceable) — **>=5.8 kernel**, recommended; hides other host
  processes' /proc. `ProtectHostname=`, `ProtectKernelLogs=`, `ProtectIPC=strict`,
  `RestrictNamespaces=`, `LockPersonality=` all recommended additions over the 2023-era set.
- `MemoryDenyWriteExecute=` now also stripped on 32-bit arch builds; fine on arm64.
- `Type=exec` is the modern default-preferred `Type` (vs `simple`) — already used. Good.
- `StartLimitIntervalSec`/`StartLimitBurst` are the modern unit names (the old
  `StartLimitInterval`/`StartLimitBurst` prefixed `Default…` moved under `[Unit]`);
  file is already up to date. In newer systemd, `systemctl restart` also resets start-limit
  burst (behavioral, not a breaking change).
- Logging: `StandardOutput=journal` + `SyslogIdentifier=` is stable; systemd 255+ (Ubuntu 24.04 =
  255.4) supports `LogFilterPatterns=`/`LogFilterPatternFilter=` (journald 252+) to **suppress
  noisy access-log lines at the unit level** — a cleaner redaction point than in-app.
- Keep `CapabilityBoundingSet=` **empty** (no caps) — with bind port >1024 you need no
  CAP_NET_BIND_SERVICE, which the unit already relies on.

**Docker Engine API (stable through v1.47+, current in 2026):**
- `docker inspect` fields unchanged and stable: `State.OOMKilled` (bool — set when cgroup OOM
  killed the process), `State.ExitCode`, `State.Status`, `State.Restarting`, `RestartCount`,
  `HostConfig.RestartPolicy {Name: no|on-failure|always|unless-stopped, MaximumRetryCount}`,
  `HostConfig.OomKillDisable`. **These are the OOM/restart introspection fields** to grep under
  the `cuda`-less host-telemetry container.
- Docker officially deprecated the standalone Engine API version pinned in old docs; the docs
  now live under `docs.docker.com/reference/api/engine/version/v1.51` (that URL redirected in
  my fetch — stable field schema retained; treat the field set below as authoritative from
  knowledge, 2023+ API, still valid).
- Key 2023→2026 notes: `--gpus` deprecated in favor of device plugin/CDI (`nvidia-container-toolkit`
  → `cdi:`, `device` requests). The compose file correctly avoids `--gpus` (right call for a
  host-telemetry collector that does zero GPU work).
- `RestartPolicy` semantics: `unless-stopped` vs `always` — for a collector you want **`always`**
  (matches systemd Restart=always); `unless-stopped` stays stopped if the user an admin stopped it.
- cgroup v2 default: OOM killer events surface as `OOMKilled:true` (informer on `State.ExitCode=137`
  + `siginfo`/`oom-kill` from `journalctl -k`/cgroup.events).
- Docker Engine-API restart behavior: container restart does NOT raise `RestartCount` for
  `on-failure` if exit code is 0; `always` increments it. Worth an alert on `RestartCount` drift.

### Journal kernel markers for OOM / NVRM / thermal / NVMe (grep strings)

```bash
# OOM
journalctl -k -g 'Out of memory|oom-kill|oom_reaper|Killed process'
journalctl -u systemd-oomd --since today        # userland oomd (memory pressure) — often the real killer on GNOME
# find OOMKilled / exit137 for the vllm container:
docker inspect -f '{{.State.OOMKilled}}/{{.RestartCount}}' <vllm>
# NVRM (NVIDIA kernel module / driver faults, XID / thermal events)
journalctl -k -g 'NVRM|nvrm|Xid|gpu.*(reset|migrate|fault)|nv_'   # add -p err for errors only
# Thermal / power-cap
journalctl -k -g 'thermal|temp|cpu_core|cpu_package|tj_max|throttl'
   # DGX Spark board thermal cap / power-limit log lines (Loki/promtail per round-5 §3)
# NVMe (drive-failure precursor + admin-qeueu stalls)
journalctl -u systemd-udevd -k -g 'nvme.*(reset|fail|timeout)|blk_update'
nvme smart-log /dev/nvme0n1   # critical_warning / percentage_used (os slow tier; skip write windows)
```

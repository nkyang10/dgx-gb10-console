# 產品 · DGX 管理平台 — Usability / 頁面 / 工作流 / 互動 / 日常使用設計

> 將底層好多門（Agent API + collectors + 狀態-01..13 + Log/MCP/告警）包裝成一個**畀 DGX 用戶嘅單一管理平台**（router 後台式 Web console `/ui`）。
> 宗旨：**「唔使逐部 SSH、唔使 set up Grafana、唔使睇 metrics 都唔明」——開唔買個網頁就知部 DGX 點、一出事就知點跟手。**
> 出處：SPEC（ASM-21 兩面）+ 各 `狀態-*`/`實作-*`。設計 DNA：暖紙底 / ink 綠 / 陶土橙 / Noto Serif TC。

---

## 1. Personas（用戶）

| Persona | 想做到 | 每日做乜 |
|---|---|---|
| **Cluster 管理員 / DevOps** | 快覽成個集群健康、出事即應、加機 | 早上巡檢、處理告警、onboard 新 node、升級 |
| **ML / 推理工程師** | 睇 vLLM 效能、排隊、模型樽頸 | 部署後睇 run、調 concurrent、查卡死/降頻 |
| **成本 / 主管** | 幾多電、幾多 Token、幾時要加 node | 月底成本 review、容量預算 |
| **Agent / 自動化** | 用 API 攞 status＋受控操作 | 畀 CI/bot 撈 `/cluster.json`、觸發告警 |

平台要**一個後台同時服務呢 4 種**：深度但簡單。

## 2. 資訊架構（IA）—— 8 個分頁

```
DGX 管理平台  /ui
├─ 總覽 Dashboard    ★ 預設首頁：cluster 健康一版睇
```

## 3. 逐頁設計

### 3.1 總覽 Dashboard（首頁）
```
┌ 群組狀態：🟢 4/4 online ─ 告警 2 (1 crit)    [live ▸]
├ 節點卡片（橫排）          ── 每張：健康、GPU util、temp、vLLM 積壓
│   [dgx-01 🟢]  [dgx-02 🟡 過熱]  [dgx-03 🟢]  [dgx-04 ⚠️ offline]
├ 即時指標 strip            ── 總 tok/s、總 RPS、總能耗、最高 temp、隊列總和
├ 警報 feed（最新 5）       ── 一撳 drill-down → 該節點相關頁
├ 熱降頻 / 最熱 node 警示
└ 24h sparklines：util·temp·tok/s per node
```
- 開盒 5 秒內答：**「成個集群而家好唔好？有冇要理？」**
- 每張 node 卡一撳 → 入節點頁。

### 3.2 節點 Nodes（每部深入）
- 上：硬件摘要（GPU util/temp/power/clocks、**throttle reason 細分**、UMA mem、CPU/RAM、NVMe wear、disk TTF）
- 中：**熱矩陣**（溫度 + SM 頻率比率 + throttle bits + util 四格）、節流史 timeline（sparkline 標降頻事件）
- 下：fabric（RDMA 各 link Gbps + link 狀態）、services（systemd/docker）、container OOM/restart
- 右欄：該 node 最多 3 個最重要警報 +「去日誌 / 去推理」shortcut

### 3.3 推理 Inference（⭐）
- **隊列實時**：running / waiting 數字 + 個別 request 表（若 enable request 追蹤）— **「有冇積壓？點解？」**
- **性能圖**：tok/s（decode/prefill）、RPS、TTFT/ITL/e2e **avg + P95**、queue time
- **Per-model 卡**：每 model 獨立吞吐/latency/backlog + SLO goodput
- KV-cache 用率 + prefix hit + preemption（飽和 → 提議「加 node / 減 concurrency」）
- 引擎狀態：**sleep / idle / active**（醒目 indicator）
- 控制：abort-by-id / pause / resume（受控，見 3.7）

### 3.4 容量 & 成本
- 容量預測：每 node disk TTF、KV/記憶體 headroom 趨勢；（「幾耐到 95%？」）
- 能耗：kWh/日、成本、idle vs active 分帳
- Token 會計：per-model 每日 tokens、$/1M、cache 慳、預算 bar（80%/100% 警告）
- **「要唔要加 node？」**一次界清楚出嚟（容量/效能/成本 3 個角度 + 建議）

### 3.5 告警 Alerts
- 活告警（severity 分級、acknowledge/silence）
- 告警歷史（點出、持續、解除）→ 時間線
- 每條：觸發原因（expr）+ drill-down 去相關頁別
- （Prometheus 對接時：同 Grafana/Alertmanager 同步）

### 3.6 日誌 Logs
見 `實作-Log設計.md`—— node×source 樹、level 色、filter、live tail、marker banner、正規化 schema。

### 3.7 控制 Control（受控，OD-4）
```
[dgx-02] vLLM  ──  [▶ Resume] [⏸ Pause] [✕ Abort req #147] [DRY-RUN]
已關：sleep(1-2) —— ⚠️ GB10 sleep-wake crash（唔 surface）
```
- 每個 action：**先 dry-run「影響 N running / M waiting」** → 確認 → 執行 → audit log
- 全平台 **read-only 預設**；控制要「開啟控制模式」先見呢頁

### 3.8 設定 Settings
- Cluster：`nodes[]`（加機 template）、token、mgmt/mcp/auth、retention
- 告警 rules 開關／閾值、Webhook/Telegram push
- Appearance（light/dark）、授權（admin 先睇 security）

## 4. 關鍵 Workflow（用家實際點做）

### W1 · 日常早巡（2 分鐘）
總覽 → 見有 🟡 dgx-02 → 撳入 Nodes → 熱矩陣見到「temp 高 + clock 降 + thermal bit」→ 行 Ingen Alerts 認識 → 一撳過去 Logs（kernel）確認 → ack 告警 → 完。

### W2 · 點部署後睇 run
部署新 model → Inference 見 per-model 卡 → 睇 TTFT P95 + 隊列 → 見 waiting 一直升 → 撳 Control 睇 dry-run → 決定係咪 pause 下調 concurrent → audit。

### W3 · 出事先應（Incident Response）
Alert bell：`vLLM engine dead` → 撳入 → 見 engine indicator 🔴 + `/health` fail → 一撳去 **Logs(vllm, level=err)** → 見爆 line → 撳去 **Control** abort 卡死 request → 重開容器 → 埋 postmortem（Logs markers 幫手）。

### W4 · 加第 3 部 DGX
Settings → Cluster → 加 `dgx-03` 一行 + 複製 install 指令 → 新機跑 → 總覽見 dgx-03 彈出嚟（自動 onboard）→ 岩。

### W5 · 每月容量/成本 review
Capacity&Cost → 睇 disk TTF + 能耗分帳 + Token 會計 → 見「三月後加 node」→ 出報告（export）。

## 5. 互動 Pattern（成個平台一致）

- **Live 開關**：右上角 global toggle（poll `/cluster.json` 5s 或 SSE /follow）；預設 on。
- **Drill-down**：一切可撳 —— card→node→熱矩陣→logs；QR 跨頁別 drill（alert→log→control）。
- **Filter 好讓 (sticky)**：node/時間/level 揀咗之後，跨頁別留住（好讓成個 cluster 一致）。
- **色碼**：severity 一致（紅=crict/降頻，橙=warn，灰藍=info）；力度色只嚟熱/功率/卡死。
- **Empty/loading**：node offline → 灰化卡 + `error_message`；無 log → 「無配對，試其他 filter」。
- **Command bar（`/`）**：快速跳去 node / model / log source / alert。
- **Keyboard**：`j/k` 行選擇、`g h` goto、`?` shortcut（監控後台慣例）。
- **響應式**：desktop 主；tablet 可監睇；mobile 淨警報 view。

## 7. 平台體驗要點（Usability checklist）

- [ ] **開盒 5 秒知健康**（首頁 summary、唔使 click）
- [ ] **每條 alert 一撳有下文**（drill-down 到 log/控制）
- [ ] **控制唔怕撳**（dry-run + 確認 + audit；read-only 預設）
- [ ] **不要用家識 PromQL / NVML**（全部中文化、圖表化）
- [ ] **跨 N 節點一致**（node selector + 統一 filter）
- [ ] **出事可以 remote 快應**（唔使 SSH / 入 server room）

## 8. 落地對應

- `src/ui/`：SPA（若 OD-6 揀輕量 HTML/JS；或 Flutter 要原生 apps 先）分頁 `dashboard/nodes/inference/capacity/alerts/logs/control/settings` ＋ router。
- 數據：全部由 gateway `/cluster.json` + `/api/logs` + `/api/alerts` + `/api/inference` + `/api/capacity` 餵（Agent API 同源，consistency）。
- 交互：live poll / SSE；drill-down 用 query param 接頁（`/ui/nodes/dgx-02?tab=thermal`）。
- 現有資料：`docs/references/dgx-*` schema 餵 Pydantic schemas 再 render。
